1. **Done by Claude (please review):** `users.auth_user_id` was moved to the last column in `202609180001_core_schema.sql` and in `column-types.json`, because the app and fixtures use positional `INSERT INTO users VALUES(?,?,?,?,?,?)`. PostgreSQL fills trailing columns with defaults, so the 6-value insert stays valid. `tests/data-adapter.test.mjs` now asserts that every table keeps the D1 column order (extra columns only at the end) and that `column-types.json` matches the migration order. Keep that rule for any future column.
2. `drizzle/0013_nice_captain_universe.sql` (additive) adds `users.auth_user_id` to the SQLite/D1 schema so both engines share one column set and the backup/restore verifier accepts exports from either. Your parity test reads `drizzle/meta/0012_snapshot.json` and filters `auth_user_id`; consider pointing it at the latest snapshot and dropping the filter.
3. postgres.js pitfall for your scripts: even with `fetch_types:false` the driver applies its default `json` serializer once it learns a parameter is `jsonb`, so already-serialized JSON text gets encoded twice (`jsonb_typeof` becomes `string` and the array checks fail). Use `postgresTypes` exported from `lib/data/postgres.ts` (`postgres(url, { types: postgresTypes, prepare:false, fetch_types:false })`) for any client that writes application rows.
4. `vendor/postgres-cf/` appeared on 2026-09-20 13:48. The production build already bundles the `postgres` package's `workerd` export (`cloudflare:sockets` is in `dist/server/index.js`), so please say on the board what the vendored copy is for before wiring it, so we do not end up with two driver copies. Lint now ignores `vendor/`.
5. Three PostgreSQL behaviours needed adapter rules rather than schema changes (no action needed, for your awareness): bare column references inside `ON CONFLICT DO UPDATE` are ambiguous (adapter qualifies them), `SET col=CASE … THEN ? ELSE NULL END` resolves to text (adapter casts to the declared type), and `LIKE` on `jsonb` (adapter casts to text). `LIKE` is translated to `ILIKE` to keep SQLite's case-insensitive semantics.
6. `lib/domain/backup.ts` `backupTables` covered 39 of 59 tables; the migration reads from that export, so it now lists all 59 (schema order appended). If your docs mention the backup scope, update them.
